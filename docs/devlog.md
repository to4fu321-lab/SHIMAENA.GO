- **提案（本人の判断待ち）**: 拠点を「実在の家の形」で塗ると、架空の人物でも実在の家を指してしまう。代わりに「50m 四方のマス」を塗る陣取り方式にすれば、家を特定できず、最初に話していた"地図取り合戦"の見た目にも近い。spec の「建物の形を塗る」を変えることになるので確認したい。
- 次: T04 ゲームの計算（得点・重要度・小タスク・ヘルプ半径・シャッフル）。
- これから: T04 ゲームの計算（得点・重要度・小タスク・ヘルプ半径・週の集計・シャッフル）
- T04 完了: `lib/game/` に計算をまとめた。得点（spec の得点表の全9行にテスト）、重要度と必要人数、小タスク分解（5・15・30分）、ヘルプ通知の発火条件と半径（300→600→1000m、段階で重ならない）、週（日曜はじまり）と称号、チームのシャッフル（強さ順の蛇行ドラフトで4人ずつ・強さも均等）。テスト31本。
- 詰まったこと: シャッフルの乱数が弱く、週が変わっても同じ組み合わせになっていた。テストで見つけて乱数を差し替えた。
- 決めたこと（spec にない細部）: 完了点・早朝点は1人ごと。依頼者本人の参加点は人数の多いチームに入れる。週の目標は「そのチームが関わった軒が全部 8:00 まで」。
- 次: T05 Claude 呼び出し（キーなしはモック）。
- これから: T05 Claude 呼び出し（レベル判定・司令官、キーなしはモック）
- T05 完了: `lib/claude/` に Claude 呼び出しを作った。モデルは Claude Opus 5.5、答えは構造化出力（zod の形どおりの JSON が保証される）、採点表 `data/rubric.json` を毎回システムに入れてキャッシュ。安全判定で断られたときは自動で別モデルに切り替える設定（fallbacks: default）も入れた。レベル判定と司令官（重要度・割り当て・LINE の文面・まとめ）を用意し、キーがない間はモック（T04 の計算）で同じ形を返す。

- これから: T06 デモ操作画面 /admin（ボタンで朝の流れを再現、保存はメモリ）
