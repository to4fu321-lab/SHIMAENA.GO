# シマエナGO 要件定義・仕様・機能一覧（11/3 時点）

寒い冬は、くっついて乗り切る。
雪の朝に LINE で点呼が届き、町内のランダム3チームがひとり暮らしの家の雪をどける。参加するほど、その朝だけのカードが増える。

## 1. 要件定義

### 対象と課題
- 対象: 札幌の町内会ひとつ（デモは架空の「しらかば町内」）。一軒家にひとりで暮らす高齢者と、その近所の人。
- 課題: 雪の朝、玄関から道路まで出られない。頼みにくい。誰がどこで困っているか分からない。「ありがとう」だけでは人が集まらない。
- 既存との違い: お金のマッチングではなくチーム戦。年1回のイベントではなく毎朝。地図・チーム・ご近所の顔がある。

### 登場する人
- 依頼者: 雪かきをお願いする人。点呼に1タップで答えるだけ。LINE を使う。
- 手伝う側: 若者〜高齢者。朝に動ける分数を答え、行って、写真を1枚送る。LINE と地図を使う。
- 家族: 依頼者の代わりに登録でき、完了や返事なしの通知を受け取る。
- サポーター: 町内会役員役。1km まで呼んでも人が集まらないときの最後の連絡先。
- 運営（デモ操作）: 朝の流れをボタンで進める。DB とメニューの準備。/admin を使う。

### 機能要件
1. 登録: 友だち追加 → 役割 → 位置情報 → 2問。依頼者は Claude がレベル判定、手伝う側はチーム配属。家族の代理登録と連携コード。
2. 1日の流れ: 前夜 21:00 の予告（翌朝 6:00 までに 5cm 以上）、6:30 の点呼（1問）、6:40 の作戦配信、「行く」、写真で完了、完了直後の通知とカード、日中の「いまからやる」、日曜のまとめ。雪のない日は何も送らない。
3. ミッション: 1軒＝1ミッション。5分単位の小タスクに分解。偵察・補給は常にある5分タスク。
4. ヘルプと見守り: 人手不足は 300m → 600m → 1km → サポーター。返事なしは灰色点滅、声かけ依頼、家族通知。体調や医療の判断はしない。
5. 得点とチーム: 得点表どおり。3チームを毎週日曜にシャッフル。個人順位は出さない。
6. 地図: 50m マスのぬりえ。状態色。得点バーと雪HP。自分の割り当てと3つのボタン。
7. カード: その朝だけ、二度と発行しない。レアでタッチが変わる。消印。SNS 用の書き出し。
8. 家族通知: 終わりました／返事がありません／今週は N 回。
9. Claude の役割: レベル判定・司令官・写真確認・カード・週末。すべて JSON、採点表を毎回渡す。
10. LINE のメニュー: 地図／カード帳／いまからやる／あそびかた／設定。

### 非機能要件と約束ごと
- スマホ表示が最優先。本文 18px 以上、ボタンは少なく大きく。
- 実在の氏名・住所・電話番号をリポジトリに入れない。地図に氏名を出さない。位置は 50m 単位で表示し、正確な場所は割り当てられた人の LINE にだけ届ける。
- AI は体調や医療について判断しない。
- チーム色に赤と緑を使わない（地図の状態色と区別）。
- 鍵はコードに書かない。鍵がない環境でも、同じ流れがモックで最後まで動く。
- 期間中（11/2〜11/8）の新規制作のみ。デモ用データは架空。
- 外部サービス: Claude API、LINE Messaging API ＋ LIFF、Neon、Vercel（Cron）、Open-Meteo、OpenStreetMap。
- LINE 無料プランはプッシュ月 200 通なので、通知は1人1回にまとめる。

## 2. 仕様

### 登録（冬の初めに1回）
- 依頼者: 「どちらですか」→ 自宅の位置 →「一人だと何分？（15／30／60以上／わからない）」「どこまで？（玄関前／車庫前／道路まで）」→ Claude がレベル1〜3。
- 手伝う側: 同じ →「朝は何分動ける？（15／30／60）」「道具はある？」→ ランダムにチーム配属。
- 代理: 家族が「家族の代わりに登録」→ 親の家の位置と2問 → 6桁の連携コードで本人や他の家族を紐づけ。

### 1日の流れ
- 前夜 21:00: 予報が基準を超えたら司令官が予告「明朝 6:30 に点呼。予想 12cm。長靴と手袋を」。操作なし。
- 6:30 エナガ点呼: 依頼者「今朝、玄関は出られそうですか？」はい／いいえ／一緒なら。手伝う側「今朝、何分動けますか？」0／15／30／60。1タップ。
- 6:40: 司令官が家ごとに重要度と必要人数を決め、チームに割り当てて配信。
- 6:40〜: 地図が色づく。足りない家は赤点滅。「行く」で確定。
- 現地: 小タスクをこなし、写真1枚で「終わりました」。
- 完了直後: Claude が写真を確認 → 得点 → 依頼者と家族に通知 → カード。
- 日中: 「いまからやる（5／15／30分）」で近くの小タスクを1件。
- 日曜: 「今週の群れ」実況、チーム順位、称号、翌週のチームをシャッフル。

### ミッションと小タスク
- 玄関前の通路（5分）／階段の砂まき（5分）／雪捨て場まで1往復（5分）／車庫前（15分）／道路まで（30分）。
- 偵察（写真1枚で「ここまだ」）と補給（お茶・カイロ）は常に5分タスク。
- 「一緒なら」と答えた依頼者は必要人数を1減らし、本人の参加も3点。

### ヘルプ通知と見守り
- 発火: (a) 開始20分前に人数不足 (b) 現場の「人手が足りない」ボタン (c) 作戦配信後の新しい「いいえ」。
- 通知先: 近い順に 300m → 600m → 1km、全チーム。文面に「5分でもOK」の小タスク。間に合わなければサポーターへ。
- 返事がない依頼者の家は灰色点滅 → 近所に「声かけお願い」→ 家族にも通知。
- 体調や医療の判断はしない。

### 得点（お金に換えない。週＝日〜土）
- ミッション完了: 10
- 7:30 までに完了: +5
- 赤点滅の家に駆けつけ（自分の割り当て完了後のみ）: +10
- 同じチーム2人以上で1軒: 各 +5
- 2チームが同じ家で合流: 両チーム +5
- 偵察／補給／依頼者本人の参加: 3
- 週の目標（全軒 8:00 までに完了）: チーム全員 +20
- 週の出撃日数: 3日で称号、5日で称号＋レアカード確定
- チーム: サルビア（青 #2F6FE4）／マリーゴールド（橙 #FF8A3D）／ルピナス（紫 #9B5DE5）。個人順位は出さない。

### 地図
- Leaflet ＋ OpenStreetMap。建物の形は背景に淡く。塗るのは 50m 四方のマス。
- 状態色: 白＝未対応／赤の縁取り点滅＝人手不足／チーム色の縁取り＝向かっている／チーム色で塗り＝完了／灰点滅＝返事なし。
- マスの中に複数の家: 人手不足を優先／全部終われば塗る／途中は薄く。
- 上に3チームの得点バーと今朝の雪HP（降雪量×拠点数）、下に自分の割り当てと「行く」「終わりました」「人手が足りない」。

### ありがとうカード
- その朝に動いた人だけ。二度と発行しない。発行枚数＝その朝の出撃人数。
- 載せる: レア度ピル／デザイン名＋英語副題／来た人の名前／日付・チーム／右上の消印（町内名・排雪kg・No.○/○・日付）。お宅の名前は載せない。
- 絵は Claude の指示で SVG を図形から組み立てる（画像生成AIは使わない）。基本はパステル×ネオン×メンフィス柄。耳あて＝チーム色、シマエナガの数＝来た人数。
- レア: 早朝＝80sレトロウェーブ／大雪＝切り絵／連続5日＝ドット絵／混成＝鈴木英人系。
- 正方形と 4:5 で書き出し。10枚で町内会からのご褒美（デモでは架空の銭湯券）。

### やらないこと
音声・電話入力／決済／他町内との比較／個人順位／医療・体調の判断。

## 3. 実装した機能

### 画面
- /: 入口（あそびかた／地図／カード帳／デモ操作）
- /rules: あそびかた（手伝う人は3つだけ、手伝ってほしい人は1つだけ、チームと点数、持ちもの、けがをしないために）
- /map: 50m マスのぬりえ地図、得点バーと雪HP、自分の割り当て、「行く」「終わりました（写真）」「人手が足りない」。LINE から開くと LIFF で本人を判定。デモは ?as=h3。
- /cards: カード帳。表面は SVG、裏面、正方形と 4:5 の保存、あと N 枚で銭湯券。
- /admin: 前夜の予告 → 点呼 → 架空の住民の回答 → 司令官 → 完了 → 駆けつけ → 日曜のまとめ。ヘルプ通知を次の輪へ。DB を準備する。リッチメニューを作る。

### LINE
- 登録の会話、「登録」でやり直し、家族の代理登録と6桁の連携コード（署名検証つき Webhook）。
- 点呼の答え、作戦のあとの遅い答え（「はい」で取り下げ、「いいえ」で人を集める）。
- 「行く／今朝は行けない」、写真を送ると Claude が確認して完了。
- ヘルプ通知「行く（5分でも）」、返事なしの「声をかけに行く」、「いまからやる」。
- プッシュは1人1回にまとめる。リッチメニュー5ボタン（画像は SVG から）。

### 自動処理（Vercel Cron、CRON_SECRET で保護）
- 21:00 JST: Open-Meteo で降雪を見て、5cm 以上なら予告。日曜は先に「今週の群れ」。
- 6:30 JST: 点呼。6:40 の作戦配信は Hobby プランの制限で cron に置かず、6:40 以降に答えが届いたとき自動配信（Pro なら cron に足すだけ）。
- ヘルプ通知の次の輪は、Webhook が動くたびに5分間隔で確認。

### Claude の役割（JSON、採点表 data/rubric.json を毎回渡す。キーがなければモック）
- レベル判定: 2問 → レベル・必要人数・小タスク・一言
- 前夜の予告: 予報 → 予告文
- 司令官: 予報・答え・拠点・手伝う人 → 重要度・必要人数・割り当て・1人ずつの文面・まとめ（答えは点検してから使う）
- 写真確認: 写真 → 雪が除かれたか・通れるか・凍結・一言
- カードの文字: 状況 → デザイン名・英語副題・排雪kg と換算
- 週末の実況: 今週の集計 → 実況文と来週への一言

### データ（Neon、素の SQL。鍵がなければメモリ）
参加者・拠点・家族の紐づけ・登録の途中経過・カード（表裏の SVG）・朝の状態（1朝ぶんを JSON で1行、日付で残す）。/admin の「DB を準備する」で表の作成と架空データの投入。

### 仕様と違う点・決めた細部
- 塗るのは建物の形ではなく 50m マス（11/2 に本人が決定）。
- 翌週のシャッフルは計算（出撃回数と体力の蛇行ドラフト）。Claude は実況文だけ。
- 「◯枚限定」はその朝に出撃した人数。通し番号は完了順。
- 家族への完了通知に写真は付けていない。
- サポーターは環境変数 SUPPORTER_LINE_USER_IDS で指定。
- ホログラム風の動きは SVG で見るときだけ（LINE の PNG は静止）。
