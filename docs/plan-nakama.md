# なかま機能（ゆるく合流・雪かきバトン・再会）の実装計画（11/5）

本人の指示書「自由参加型AI交流・再会機能」への計画。spec v1.13 として取り込む。
いちばん大事なこと: **いつでも自由に・ひとりで参加できる今の仕組みは変えない**。交流は「したい人だけ」。

## 1. 今の機能と、今回の機能の対応
| 今回の機能 | 使う今の仕組み | 足すもの |
|---|---|---|
| A ゆるく合流 | ソロ出動 `/solo`・「10分だけ参加」（`joinAction`）・地図の家の番号・「いま雪かき中」・LINE の push と postback・夜の防犯（`lib/night.ts`）・警報の日のお休み（`lib/storm.ts`） | 今日のスタイル（4択）、合流の候補、合流の提案と同意、LINE の「一緒にやる／今回はやめておく」 |
| B 雪かきバトン | ソロの台帳 `solo_logs`（活動したマス・写真の確認済み）・家の完了・完了画面（`SoloClear`・`MissionClear`） | 完了画面の「次の人へバトン」、地域（約250m四方）のバトンの一覧、ありがとう／続きをやります |
| C 再会 | カード `cards`（同じ家で一緒に受け取った人＝前回の仲間）・完了画面 | 完了画面の「次は？」（4択）、次回の候補に反映、同じ人ばかりにしない、初参加の人を迎える |
| AI | 隊長の口調（採点表 voice）・Haiku の短い文・点検してから使う | 採点表 `nakama`、合流の誘いの一文、バトンのつながりの一文 |

**AI司令官（朝の割り当て）は変えない**。割り当ては「朝の人」をチームに配るだけで、自由参加の人には関係しないため。交流は割り当ての外で、本人が選んだときだけ動く（「交流希望を無視したチーム編成」をしない一番確かな方法）。

## 3. DB（足すだけ。今の表・データには触らない）
すべて `create table if not exists`。表がなくても最初に使うときに作る（道の報告と同じ）。
- `nakama_prefs`（1人1行）: `next_wish`（また一緒に／新しい人と／ひとりで／特になし）、`today_mode`・`today_date`・`today_at`（今日のスタイル）
- `meetups`（合流の提案）: 誰から・誰へ・種類（再会／新しい人／歓迎／近く）・時間（今から10分以内／今日のどこか）・場所（地図の家の番号 or それぞれの家の前）・状態（提案中／成立／見送り／期限切れ）・誘いの一文
- `batons`: 誰が（画面には出さない）・日付・地域（約250m四方）・何をしたか・どこまで（終わった／途中）・ひとこと・写真で確認済みか・つながりの一文
- `baton_reactions`: バトンごとに1人1回（ありがとう／続きをやります）

「前回の仲間」は今あるカードの表から作る（同じ家・同じ時に一緒にカードを受け取った人）。成立した合流も仲間に数える。年齢は集めない。

## 4. サーバーの処理
- `setTodayMode`（今日のスタイル）／`setNextWish`（次は？）
- `listCandidates`: プログラムが選ぶ。相手も**今日「一緒に」系を選んでいる人だけ**（3時間以内）。家どうし 600m 以内、夜とお休みの日は出さない、今日見送られた相手・7日で2回見送られた相手は出さない、ひとり 3件まで
- `propose`（自分が押す＝自分の同意）→ 相手に LINE で1回（1人1日3件まで）＋アプリにも表示
- `respond`（相手が押す＝相手の同意）→ 両方そろったときだけ「成立」。期限（今から10分以内は30分、今日のどこかは19時）を過ぎたら成立しない。見送りの理由は相手に伝えない
- `leaveBaton`／`reactBaton`／`areaView`（地域のバトン・今日の参加人数）

## 5. 画面と LINE
- **自由参加は今のまま1タップ**。ソロの画面の上の帯に「👥 だれかと一緒に（任意）」の1行だけ足す。押すと `/nakama`。
- `/nakama`（1画面）: 今日のスタイル（4つの大きいボタン）→ 合流の候補（最大3）→ 届いた誘い（一緒にやる／今回はやめておく）→ 成立した合流（相手の呼び名と場所、「◯番の家へ」）→ この地域のバトン
- 完了画面（ソロ・チーム）: 「次は？」4つのボタン（任意・押さなくてよい）と「次の人へバトン」（決まった言葉3つ＋ひとこと30字）
- LINE: 相手に「近くの人が、10分だけ一緒に雪かきしませんか、と言っています」＋「一緒にやる」「今回はやめておく」「画面で見る」。返信だけで答えられる

## 6. AI の役割
- 採点表 `nakama` を毎回渡す。Haiku（短い文）。キーがないときは決まった文。
- 書くのは「合流の誘いの一文（40字）」と「バトンのつながりの一文（60字）」だけ。**書き込みのときだけ作る**（画面を開くたびには呼ばない）
- 点検: 長さ、入力にない数字を使っていない、恋愛・感情を推し量る言葉がない、名前・番号・場所の言い方がない → だめなら決まった文
- AI がしないこと（プログラムで止める）: 同意なしの成立、相手選び（候補はプログラムが選ぶ）、危険な作業の判断、場所の公開、参加の強制

## 7. 安全とプライバシー
- 候補の段階では、新しい人の呼び名も距離も出さない（「近くの人」「初参加の人」だけ）。前回の仲間は、もうカードで知っている呼び名だけ
- 成立するまで、相手の呼び名・今日のスタイル・活動を相手に知らせない。成立しても家の場所は出さない（場所は地図の家の番号。行き先は今までどおり「10分だけ参加」で本人にだけ届く）
- 夜（19〜6時）とお休みの日は合流を受け付けない
- バトンに名前は出さない（「朝の活動者」）。地域は約250m四方（50m マスより粗い）。写真は保存しない（「写真で確認済み」の印だけ）。ひとことは名前・番号・場所の言い方をはじく
- ひとりで・特になし を選んだ人は候補に出ない。いつでも変えられる。断っても何も減らない（点・羽に関係しない）
