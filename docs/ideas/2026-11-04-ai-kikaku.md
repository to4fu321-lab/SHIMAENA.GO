## 0. 先に結論

**AIの仕事は「人が玄関の外に出る理由」を作ること。AIは作業を代わりにしない。AIが増やすのは、人が動く回数・会う回数・ありがとうの回数。**

判断の基準を1つだけ決めます。

> **ルールで書けることは普通のプログラムで書く。AIを使うのは、人のことば・写真・その場の空気のように、形が決まっていない所だけ。**

この基準で見ると、シマエナGOで AI が本当に効くのは次の3つの場面です。

1. **入口**: デジタルが苦手な人が、ふつうの言葉で参加できる（ボタンを押せなくてもいい）
2. **つなぐ**: 人の言葉を、相手に届く形にする（世代・言葉・気持ちの壁を越える）
3. **物語にする**: その朝に起きた本当のことを、人に話したくなる形にする（SNS と口コミ）

ランキング・称号・レベル・チーム分け・連続記録・通知のタイミングは**すべて普通のプログラム**で作ります。AI は「文章を書く」「読み取る」ところにだけ入ります。安くて、速くて、嘘をつかないからです。

**いちばんのおすすめ TOP3**（くわしくは 14 章）
1. 🟢 **ことばで雪かき依頼**: 「10時に病院だから、9時までに玄関だけお願いできるかね」→ Claude が段取りにして地図とカードへ
2. 🟢 **今朝の先生**: お願いする側の高齢者が雪かきの知恵を一言 → Claude が今朝の雪に合う知恵を選んで、手伝う人のカードへ（高齢者が「助けられる人」から「教える人」に）
3. 🟢 **隊長のひとこと（その朝専用）**: 天気・町の進み具合・その人の状態から、隊長が一人ひとりに違う一言。ただし文を作るのは「状態ごとに1回」で、安く保つ

## 1. シマエナGOのAIビジョン

### 1-1. 一文で
**「AIが人を動かし、人が街を動かす。」** AI は画面の中で完結しない。AI の成果は、AI の回答の賢さではなく、**その冬に増えた「動いた人」「顔見知り」「ありがとう」の数**で測る。

### 1-2. 他の作品との違い
| よくある AI アプリ | シマエナGO |
|---|---|
| データを読み取る | 人の**ことば**を読み取って、人を**会わせる** |
| 難しい申請を簡単に | 難しい**お願い**を簡単に（「助けて」と言いにくい人が言える） |
| 職人の知見を AI が代わりに | 地域の高齢者の知恵を、AI が**若い人へ渡す**（知恵の持ち主は人のまま） |
| 人の手間を減らす | 人の**出番を増やす** |

### 1-3. AI の3つの約束（コードと採点表に入れる）
1. **数字を作らない**: 人数・軒数・cm は計算した値だけを渡し、AI は言葉にするだけ（今の実況と同じ）。
2. **体や医療の判断をしない・無理をさせない**: 「もっとやれ」と言わない。大雪の日ほど「ひとりでやらない」「15分で休む」を言う。屋根の雪下ろしはミッションにしない。
3. **人の言葉を勝手に書き換えない**: お礼は本人の言葉が主役。AI は読みやすく整えるか、相手の言語にするだけ。名前・住所は外に出さない。

## 2. AIによる参加者10倍戦略

参加者が増える道は「入口を増やす」「続ける」「誘う」の3つ。AI が効くのは入口と誘うところで、続けるところは主にゲームの仕組み（普通のプログラム）が担います。

| 問い | 打ち手 | AI の役目 | 普通のプログラムの役目 |
|---|---|---|---|
| どうすれば参加者が増えるか | 入口を4つにする（雪かき／応援／報告／知恵） | 入口ごとの案内文、自由な言葉の読み取り | 入口のボタン、登録 |
| どうすれば毎日開くか | 雪のない日にも「5分の出番」がある | その日のミッションの説明文 | ミッションの抽選、連続記録 |
| どうすれば友達を誘いたくなるか | 誘う理由を「自分の物語」にする | その人の本当の活動から招待文を書く | 招待リンク、誰経由で来たかの記録 |
| 雪かきをしない人も参加できるか | 応援・見回り・雪の報告・知恵・お茶の差し入れ | 応援の言葉を現場に届く形に | 応援ゲージ、応援の記録 |
| 高齢者も参加できるか | ボタンを押さなくても話せば伝わる。教える側にもなれる | **ことば → 段取り**、知恵の整理 | LINE、家族の代理登録 |
| 学生・企業が参加するか | 「証明」と「ネタ」を渡す（活動の記録・社内報の文） | 学生向け・企業向けの活動まとめ文 | 活動時間の集計、証明ページ |
| 地域ごとにコミュニティができるか | 町ごとに「町の物語」と「町の先生」が育つ | 週の物語、町の知恵の本 | 町の単位、町の公開ページ |

### 10倍にする一番の鍵: 「1人が1人を連れてくる」を AI で起こす
- 今は「誘ってね」と言っても誘わない。誘いたくなるのは**自分が主役の話がある時**。
- 雪かきが終わった直後（いちばん気分がいい時）に、隊長がその人の今朝の本当の話から招待文を3つ出す。
  - 例: 「今朝、近所のおばあちゃんの玄関を5分で開けてきた。お茶もらった。次の雪の朝、一緒にどう？」
- 押すだけで LINE の友だち選択（LIFF の shareTargetPicker）。来た人は `?via=` で記録（普通のプログラム）。
- 目標の数字: **完了した人のうち3割が誘い、その3割が参加** → 1回の雪で参加者 +9%。冬に20回雪が降れば、それだけで約5.6倍。応援・報告の入口と合わせて10倍を狙う。

### 続けるための仕組み（AI ではなく設計で）
- **休んでも連続記録が切れない**（「今朝は休む」と答えたら記録は続く）。無理をさせない設計が、そのまま続ける理由になる。
- 雪のない日は「見回り」「雪の報告」「知恵を1つ」「応援を1つ」の5分。

## 3. 革新的なAI機能20案

各案: 何をする／AI が要る理由（要らないなら普通のプログラム）／重さ（小=半日・中=1日・大=2日以上）

### A. 入口を広げる（誰でも参加）
1. 🟢 **ことばで雪かき依頼** — 依頼者が自由な文（声の入力でも可）で送る → Claude が「締め切り・範囲・人数・注意」に分ける。AI が要る: 言い方が人ごとに違う。重さ: 中
2. 🟢 **ことばで点呼に答える** — 「今日は孫が来るから大丈夫」→「はい（出られる）」扱い。ボタンを押せない人の返事を拾う。重さ: 小
3. 🟡 **隊長の声で点呼**（音声合成 → LINE の音声メッセージ） — 文字を読むのがつらい人へ。AI が要る: 読み上げ用の短い文。⚠️ 仕様の「音声」とぶつかる（入力でなく出力なので、本人の判断で可）。重さ: 中
4. 🟢 **はじめての人の案内役** — 「何をすればいいの？」に、その人の状況（登録の答え・近くの仕事）から1つだけ次の行動を返す。AI が要る: 質問が自由。重さ: 小
5. 🟡 **多言語でつなぐ** — 留学生・海外から働きに来た人に、依頼とお礼を相手の言語で届け、返事を日本語に戻す。AI が要る: 気持ちを残した翻訳。重さ: 中

### B. 人をつなぐ（コミュニティ）
6. 🟢 **今朝の先生**（知恵の継承） — 依頼者の一言の知恵を集め、今朝の雪（重い・軽い・凍結）に合うものを選んでカードへ。AI が要る: 自由な言葉の整理と、状況に合う選択。重さ: 中
7. 🟢 **ありがとうの橋渡し** — 依頼者の「お茶飲んでいきな」を、手伝った人へカードの裏の一文に。高齢者の言い方を残す。（今の「ありがとう点呼」を自由な言葉に広げる）重さ: 小
8. 🟡 **現場の話のタネ** — 2人が着いたら1つだけ話題を出す。AI はなくてもよい（話題リストで足りる）→ **普通のプログラムで作る**。
9. 🟡 **町内の「はじめまして」記録** — 一緒に動いた2人が初めてなら記録し、週に「はじめて一緒に動いた組」を数える。**普通のプログラム**。週の物語の中で Claude が言葉にする。
10. 🟡 **応援の届け方** — 遠くの家族や雪かきできない人の応援を、現場の人に「誰から・どんな気持ちで」の一文で届ける。重さ: 小

### C. 物語にして広げる（SNS・口コミ）
11. 🟢 **あなたが主役の招待文** — その人の本当の活動から招待文を3案。押すと LINE の友だち選択へ。重さ: 小
12. 🟢 **今朝の物語**（実況の強化） — 「今朝、8人が動き、5軒の玄関が開いた。はじめて組んだのは3組」。数字は計算、文だけ Claude。重さ: 小（今の実況を広げる）
13. 🟡 **町の冬の本** — 週の物語と町の先生の知恵を、春に1冊（PDF）に。回覧板・町内会報にそのまま使える。重さ: 中
14. 🟡 **学生・企業・町内会向けの活動まとめ** — 学生はボランティアの記録、企業は社内報の記事、町内会は総会の報告文。数字は集計、文だけ Claude。重さ: 中

### D. ゲームを盛り上げる
15. 🟢 **雪ボスの台詞と性格** — 今朝の雪の名前（今ある）に、性格と台詞を足す。「ぼた雪のドンブリ: 重いぞ、ゆっくり来い」。討伐の時の負け台詞。重さ: 小
16. 🟢 **隊長のひとこと（状態別）** — 4章・6章。重さ: 中
17. 🟡 **称号の名付け** — 称号の条件は計算、名前と一言だけ Claude（「朝いちばんのスコップ」など）。重さ: 小
18. 🟡 **町の共同目標の提案** — 先週の数字から「今週は10軒を目標にしよう」。目標の数字は計算（先週の1.2倍など）、言い方だけ Claude。重さ: 小

### E. 安全と見守り
19. 🟢 **安全のひとこと** — 大雪・低温・強風の朝は、隊長が「ひとりでやらない」「15分で休む」を必ず言う。言う・言わないの判断は**普通のプログラム**（天気の数字で）、言い方だけ Claude。重さ: 小
20. 🟡 **見守りの声かけ文** — 点呼に返事がない家への声かけを、近所の人が言いやすい一言に。体調の判断はしない。重さ: 小

## 6. AIシマエナガ隊長のUI・UX設計

### 6-1. 仕組み（状態は計算、言葉は Claude）
```
アプリ/LINE を開く
  → 状態を決める（普通のプログラム。下の表の上から順に最初に当てはまるもの）
  → その朝のその状態の一言がもう作ってあれば、それを使う（キャッシュ）
  → なければ Claude に「状態・今朝の天気・町の数字」を渡して1回だけ作る
  → キーがない・失敗したら定型文
```
一言は**一人ずつではなく「状態×町×その朝」で作る**ので、利用者が1万人でも1日 10回ほどの呼び出しで済みます。名前などの一人ずつの部分は、定型の穴埋めで足します。

### 6-2. 状態と会話例（語尾「しま〜」「えな〜」は3文に1つまで）
| 状態（判定） | 隊長の一言の例 | 下に出すボタン |
|---|---|---|
| ① 安全注意（大雪・−5℃以下・強風） | 「今朝は重い雪だしま〜！ひとりでやらず、15分ごとに休みましょう。」 | 出動する／今朝は休む |
| ② 初回（登録して最初に開いた） | 「ようこそ！まずは5分だけ、家の前の見回りから始めてみるえな〜。」 | 5分だけやってみる |
| ③ はじめて雪かきした直後 | 「はじめての出撃、おつかれさま！今朝、1軒の玄関が開きました。」 | カードを見る／友だちに話す |
| ④ 町の目標まであと少し | 「あと1軒で今朝の目標だしま〜！近くに5分でできる家があります。」 | 近くの家を見る |
| ⑤ 3日以上来ていない | 「おかえりなさい。休むのも大事な仕事えな〜。今日は応援1つからどうですか。」 | 応援する／見回り |
| ⑥ 毎日来ている | 「5日続けて出番、ありがとう！今朝は先生のコツ『雪は朝のうちに』を試してみて。」 | 出動する |
| ⑦ 友達を誘った | 「○○さんを連れてきてくれたしま〜！群れが1羽ふえました。」 | 一緒のチームを見る |
| ⑧ 雪かきができない人（依頼者・高齢者） | 「今朝もおはようございます。玄関の雪、気にせず任せてくださいね。今朝のコツを1つ教えてもらえますか？」 | 声で答える／はい・いいえ |

- ⑤は責めない。⑧は丁寧語（見守りに関わるため語尾を付けない）。
- ①は他のどの状態より先に出る（安全が最優先）。

### 6-3. 画面（今の UI を尊重）
- **ホーム**: 今の「今日のミッション あと N 軒」の上に、隊長の吹き出し1つ（2行まで）。タップで LINE と同じ隊長カード。ボタンは今の「出動する」「5分だけ手伝う」のまま（増やさない）。
- **LINE**: 今の隊長カード（積雪ゲージの絵）の本文に、状態の一言を入れる。
- **地図**: 依頼に「9:00 まで」「玄関だけ」の札（① のことばで依頼から）。
- 文字は 18px 以上、ボタンは2つまで、という今のルールを守る。

### 6-4. デモでの見せ方（3分の中の40秒）
1. おばあちゃん役が LINE に声で「10時に病院だから、9時までに玄関だけお願い」
2. 地図に印と「9:00 まで・玄関」が出る
3. 学生役のスマホに行き先カード＋「今朝の先生: 湿った雪は少しずつ」
4. 完了 → おばあちゃんの「お茶飲んでって」がカードの裏に → 招待文で友だちへ

## 7. Claude APIの実装アーキテクチャ

### 7-1. AI と普通のプログラムの分け方
| 普通のプログラム（AI を使わない） | Claude（文と読み取りだけ） |
|---|---|
| 状態の判定、チーム分け、ランキング、称号の条件、連続記録 | 自由な言葉 → 段取り（JSON） |
| 安全注意を出すかどうか（天気の数字で） | 隊長の一言、雪ボスの台詞 |
| 誰を誘ったかの記録、はじめて組んだ数 | 招待文、今朝の物語、週の物語 |
| 得点・羽・排雪 kg の計算 | 知恵の整理と、今朝に合う知恵の選択 |
| 通知を送る時刻・相手 | 翻訳（提出後） |

### 7-2. 流れ（今の `lib/claude/client.ts` の askJson をそのまま使う）
```
LINE Webhook / 画面 / cron
   │
   ├─ 普通のプログラム: 状態・数字・安全を決める
   │
   ├─ lib/claude/*.ts: askJson({ task, input, schema })
   │     system = 隊長の設定＋採点表（毎回同じ → キャッシュが効く）
   │     input  = 計算済みの数字・状態・本人の言葉（名前・住所は外す）
   │     出力   = zod で形を確かめた JSON
   │
   ├─ 確かめる: 数字が入力と違えば定型に戻す（今の share.ts と同じ）
   │
   └─ 保存（ai_texts 表）→ LINE / 画面へ
```

### 7-3. エージェント化について
- 今週はエージェントにしない。1回呼んで JSON を受け取る形のほうが、安く・速く・テストしやすい。
- 提出後の候補: **「人が足りない家」担当のエージェント**。道具（近くの空いている人を探す・その人の今朝の答えを見る・お願いの文を送る）を持たせ、足りるまで順に声をかける。ただし送る前の上限（1人に1日1回まで、など）は普通のプログラムで固く決める。

共通: system は今と同じ「エナガ隊長＋採点表」（毎回同じ文 → キャッシュ）。下は task と input と出力の形。

### 8-1. ことばで雪かき依頼
```ts

const RequestSchema = z.object({
  intent: z.enum(["need_help", "fine", "together", "unknown"]),
  deadline: z.string().nullable(),      // "09:00"。言っていなければ null
  area: z.enum(["entrance", "garage", "road", "unknown"]),
  note: z.string(),                     // 手伝う人に見せる20字まで（名前・体調の言葉は入れない）
  askBack: z.string().nullable(),       // わからない時だけ、聞き返す一文
});
askJson({
  task:
    "お願いする方が送った言葉から、雪かきの段取りを取り出してください。" +
    "言っていないことは推測で埋めず null か unknown に。体調や病気の判断はしない" +
    "（『病院』は予定として時刻だけ使う）。note は手伝う人向けに20字まで、病名や体のことは書かない。" +
    "迷ったら askBack に、はい/いいえで答えられる聞き返しを1つ。",
  input: { text: "今日は10時に病院だから、9時までに玄関だけお願いできるかね", today: "2026-12-14", rollcallAt: "06:30" },
  schema: RequestSchema,
  effort: "low",
});
// → { intent:"need_help", deadline:"09:00", area:"entrance", note:"9時までに玄関前を", askBack:null }
```

## 10. 参加者100人 → 1,000人 → 10,000人の成長戦略

| 段階 | 誰に | 何で増える | AI の役目 | 測る数字 |
|---|---|---|---|---|
| 〜100人（1つの町内） | 町内会・家族・近所の学生 | 町内会長の一声と回覧板。家族の代理登録 | ことばで依頼（高齢者が入れる）、回覧板の文 | 依頼者の数、点呼の返事率 |
| 〜1,000人（区・近くの町内） | 大学・高校、近くの町内会 | 招待文、「今朝の物語」の SNS 共有、学生の活動記録 | 招待文、学生向けまとめ | 1人が連れてきた人数、共有の数 |
| 〜10,000人（市・雪国の町） | 企業、自治体、他の雪国 | 企業の社内チーム、町の冬の本、町ごとの公開ページ | 企業向け記事、町の冬の本、多言語 | 町の数、町ごとの継続率 |

⚠️ **全国ランキング・地域対抗戦について**: 仕様の「やらないこと」に「他町内との比較・個人順位」があります。理由は、競争にすると無理をする人が出るのと、助けが少ない町が責められるから。代わりの案:
- **全国の合計**（「今冬、全国で 3,210 軒の玄関が開いた」）— 競争ではなく、みんなの数字
- **町どうしの「エール交換」** — 先に終わった町が、まだの町に応援を送る
本人が「対抗戦も入れたい」と決めたら、仕様を変える案を別に書きます。

### 12-1. 料金（2026-10 時点の公開価格、100万トークンあたり）

| Claude Sonnet 5.5 | $2 | $10 | 物語・招待文 |
| Claude Haiku 5.5 | $0.10 | $0.50 | 隊長の一言、知恵のタグ付け |

- キャッシュから読んだ入力は約1割の料金。まとめて送る Batch は半額（週の物語など急がないもの）。
- 今のコードは全部 Opus 5.5 を使っています。モデルを分けるかは本人の判断（下の試算は両方を出します）。

### 12-2. 試算（1回の呼び出し: 入力 約4,000 トークン〔採点表はキャッシュ〕＋出力 約300）
- Opus 5.5: 1回 約 $0.01〜0.02（約2〜3円）
- Haiku 5.5: 1回 約 $0.0005（0.1円以下）

| 規模 | 雪の朝1回の呼び出し | 冬（雪の朝 40回）の目安 |
|---|---|---|
| 100人 | 写真30＋ことば20＋司令官1＋隊長10＋物語1 ≒ 60回 | Opus だけ: 約 $50（約7,500円）／分けると 約 $25 |
| 1,000人 | 約 500回 | Opus だけ: 約 $400／分けると 約 $150 |
| 10,000人 | 約 4,500回 | Opus だけ: 約 $3,500／分けると 約 $1,200 |

（写真の確認とことばの読み取りが大半。隊長の一言はキャッシュで人数に比例しない）

### 12-3. 削減策（効く順）
1. **作った文を使い回す**: 隊長の一言・物語は「状態×町×日」で1回（`ai_texts`）。
2. **AI に頼む前に普通のプログラムで片づける**: 「はい」「大丈夫」などの短い返事は言葉の一覧で判定し、Claude を呼ばない。
3. **採点表をキャッシュ**: system を毎回同じ文にする（今の client.ts はそうなっている）。
4. **短い文は軽いモデル**: 一言・タグ付けは Haiku 5.5。
5. **急がないものは Batch**: 週の物語・町の冬の本は半額。
6. **写真は小さくしてから送る**: 長い辺 1024px まで。

## 13. 他のアプリにはないシマエナGO独自のAI体験

1. **お願いが言いやすい**: 「助けて」をボタンで選ぶのではなく、いつもの言葉で言える。AI はその言葉を段取りにするだけで、言葉の持ち主は本人のまま。
2. **高齢者が先生になる**: 助けられる側の知恵が、翌朝の若い人のカードに載る。AI は知恵を作らず、運ぶだけ。
3. **AI の一言が人の数に比例しない**: 状態ごとに作るので、町が大きくなっても隊長は一人ひとりに話しかけ続けられる。
4. **休むことをほめる AI**: 大雪の日ほど「休んでいい」と言う。続ける理由と安全が同じ方向を向いている。
5. **その朝の本当の話だけ**: 数字も話も、その朝に起きたことだけ。作り話の感動ではなく、本当の話が SNS で広がる。

## 14. 最も革新的で、実装価値が高いアイデアTOP3

### 1位: ことばで雪かき依頼（デジタルが苦手な人ほど得をする AI）
- **なぜ革新的**: 多くのアプリは、慣れた人をさらに便利にする。これは、いちばん取り残されやすい人の入口を広げる。
- **なぜ AI が要る**: 「孫が来る」「病院」「玄関だけ」など、言い方が人ごとに違い、ルールでは拾えない。
- **作るもの**: `lib/claude/request.ts`（8-1）、`requests_text` 表、LINE の自由な文の受け口、地図の札、キーなしの簡単な読み取り。重さ: 中（1日）。

### 2位: 今朝の先生（地域の知恵を、AI が次の世代へ運ぶ）
- **なぜ革新的**: 「職人の知見を AI が代わりに」の逆。知恵の持ち主は人のままで、AI は運び役。高齢者に役割と会話が生まれ、孤立を防ぐ。
- **なぜ AI が要る**: 言い方がばらばらの知恵を整理し、今朝の雪に合うものを選ぶ。
- **作るもの**: 点呼のあとの「コツを1つ教えて」、`tips` 表（同意つき）、行き先カードの1行。重さ: 中。

### 3位: あなたが主役の招待文（参加者を増やす一番の近道）
- **なぜ革新的**: 「誘ってください」ではなく、その人の今朝の本当の話を、誘いたくなる文にする。
- **なぜ AI が要る**: 一人ひとり違う活動を、自然な誘い文にする。
- **作るもの**: 完了画面の3案、LIFF の友だち選択、`invites` 表で誰が誰を連れてきたかを数える。重さ: 小。
