## 見るもの
1. **画面** `.tenken/*.png`（スマホ幅 390px。なければ `npm run build` → `npm run tenken` で作る）。Read で画像を開いて、**初めて使う町内の人**（60〜80代、LINE は使える、ゲームは初めて）の目で見る:
   - 何をするボタンか分かるか。押したら何が起きるか想像できるか
   - 言葉が分かるか（カタカナ・ゲーム用語・略語）。「出撃」「HP」「ミッション」などは仕様の用語なので変えないが、説明がないと分からない場所は指摘する
   - 文字が小さい、ボタンが小さい、色が薄い、重なっている、切れている
   - 流れが途切れる（次に何をすればいいか分からない画面）
2. **差分** `git log --since="2 days ago" --stat` と `git diff HEAD~10 -- app components lib`（大きければ最近の 5コミット）。不具合の型:
   - 条件や変数の取り違え、`?as=` の人と cookie の人の扱い違い、日本時間（`lib/jst.ts`）とサーバー時間の混同
   - DB あり（Neon）と DB なし（メモリ）で挙動が違う所、`ANTHROPIC_API_KEY` なし（モック）で落ちる所
   - 入力が空・長い・絵文字のときに壊れる所
3. **放置**: `docs/devlog.md` の最近の「詰まったこと」「次」で、まだ片付いていないもの

## 報告の型（最後のメッセージに。これが点検ループの材料になる）
件数は多くても **10件まで**。確信の高い順。1件 2行。
```
🐞 不具合｜場所（ページや file:line）｜何が起きる｜根拠（スクショ名・コードの行）｜直し方の見当（小／大）
❓ 意味不明｜場所｜誰がどう迷うか｜直し方の見当（文言案があれば）
💡 改善｜場所｜何が良くなるか｜重さ（小／中／大）
```
最後に「上位3つ」とその理由を1行ずつ。

## 守ること
- 約束ごとに反する指摘はしない: 医療・体調の判断／個人順位／お金／他町内との比較／実在の氏名・住所／地図に氏名／チーム色に赤と緑。
- 仕様の用語を「変えろ」とは言わない。「説明を足す」「並びを変える」の形で言う。
- 本人はプログラミング初心者。やさしい日本語で短く。
